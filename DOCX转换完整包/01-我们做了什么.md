# 我们做了什么？LaTeX → DOCX 转换详解

**目标：** 把LaTeX格式的学位论文转换成Microsoft Word格式（.docx）

---

## 🎯 为什么要转换？

导师或学校可能要求提交Word格式，但论文是用LaTeX写的。直接复制粘贴会丢失格式、公式和图片。

---

## 🔧 转换流程（技术细节）

### 第1阶段：LaTeX → Markdown
**工具：** Pandoc

```bash
pandoc main.tex -o thesis.md \
  --from=latex \
  --to=markdown \
  --standalone \
  --number-sections
```

**结果：**
- ✅ 文本结构保留
- ✅ 公式转换成通用格式
- ⚠️ 图片引用丢失（这是正常的）

---

### 第2阶段：Markdown → DOCX（基础版）
**工具：** Pandoc

```bash
pandoc thesis.md -o base.docx \
  --from=markdown \
  --to=docx \
  --standalone \
  --number-sections
```

**结果：**
- ✅ 生成可编辑的Word文档
- ✅ 公式正确显示（可以编辑）
- ❌ 还没有图片

**为什么公式能正常显示？**
Markdown中的公式使用通用的LaTeX语法（如 `$E=mc^2$`），Pandoc会自动转换成Word的公式编辑器格式。

---

### 第3阶段：处理图片（最复杂的部分）

#### 问题1：单独的图片丢失了
**原因：** Pandoc转换时，图片的路径信息丢失了。

**解决方案：** 用Python脚本智能插入
1. 读取生成的DOCX文件
2. 遍历所有段落，找图注（如"Figure 2.1: Flowchart..."）
3. 根据关键词匹配，在图注前插入对应的图片

**例如：**
```python
if "Flowchart of the developed SOH" in paragraph.text:
    paragraph.insert_paragraph_before().add_picture("figures/fig1.png")
```

#### 问题2：多子图面板怎么办？
**原因：** LaTeX中的Figure 4.2是由7个小图拼成的，像这样：
```
[Cell2] [Cell3] [Cell4] [Cell5]
[Cell6] [Cell7] [Cell8]
```
转换过程中这些拼接信息会丢失。

**解决方案：** 用Python的PIL库合成
1. 读取7个单独的子图PNG文件
2. 创建一个大的空白画布
3. 按2行4列（或其他布局）排列这7个子图
4. 保存成一张完整的大图
5. 插入到DOCX中

**代码逻辑：**
```python
# 伪代码
images = [load("cell2.png"), load("cell3.png"), ...]
canvas = create_blank_image(width=2000, height=1000)
for i, img in enumerate(images):
    row = i // 4  # 第几行
    col = i % 4   # 第几列
    paste(img, position=(col*500, row*500))
save(canvas, "oxford_panel.png")
```

## 🤖 使用了并行处理

为了加快速度，我们同时开了**3个Agent**（相当于3个工人同时干活）：

### Agent 1：合成CALCE/MIT面板
- 输入：6个子图PNG
- 输出：`figure_4_3_calce_mit_panel.png`
- 布局：2行3列或3行2列

### Agent 2：PDF转PNG + 检查公式
- 任务1：把PDF格式的图转成PNG（fig4_n_agents, fig4_storage）
- 任务2：验证DOCX中的公式编号是否完整

### Agent 3：合成Oxford面板
- 输入：7个子图PNG  
- 输出：`figure_4_2_oxford_panel.png`
- 布局：2行4列（第二行3个）

## 🔬 技术栈

### 使用的工具
1. **Pandoc** - 文档格式转换的瑞士军刀
2. **Python 3** - 自动化脚本语言
3. **python-docx** - 操作Word文档的Python库
4. **Pillow (PIL)** - Python图像处理库
5. **pdf2image** 或 **PyMuPDF** - PDF转图片

### 为什么不能用其他方法？

#### ❌ 方法1：直接 LaTeX → DOCX
- 图片全丢
- 公式变成乱码
- 表格错位

#### ❌ 方法2：PDF → DOCX
- 整个页面变成图片
- 完全不能编辑
- 文件巨大

#### ❌ 方法3：复制粘贴
- 格式全乱
- 公式变成普通文本
- 图片要一个个手动插入

#### ✅ 我们的方法：LaTeX → Markdown → DOCX + Python脚本
- 文本完美保留 ✓
- 公式正确转换 ✓
- 图片智能插入 ✓
- 可以继续编辑 ✓

## 💡 经验总结

### 成功的地方
1. **分阶段转换**比一步到位更可靠
2. **并行处理**大幅提高效率
3. **智能匹配**关键词插入图片很有效
4. **Python脚本**让复杂任务自动化

### 遇到的困难
1. **多子图面板**需要手动合成（无法自动识别）
2. **表格格式**在不同系统间转换很困难
3. **公式编号**自动检测不可靠（需要人工验证）

### 如果重来会怎么做
1. 提前规划好图片的命名和组织方式
2. 表格直接从PDF截图，不尝试自动转换
3. 准备更多的关键词变体来匹配图注

## 🎓 适用场景

### 这个方法适合：
- ✅ 需要把LaTeX论文转成Word提交
- ✅ 保留公式的可编辑性很重要
- ✅ 愿意花一点时间调整表格和细节

### 这个方法不适合：
